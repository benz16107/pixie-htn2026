# Sponsor tracks: what we built, and what is actually verified

One row per track Pixie targets. The track list is the pitch map in `docs/PITCHES.md:11-26`
(twelve pitches), cross-checked against the prizes already ticked on Devpost
(`docs/arena/grounding.md:6`).

Read the last column before you say anything on stage. "Verified" means a code path a test or a
checked-in fixture exercises, or something we ran and recorded. "Unverified" means the code exists
and has never been proven end to end, usually because it needs a live key. If a feature only runs in
dry mode, the row says so.

Ordering follows the pitch map, not importance.

## The five things to say before a judge finds them

1. **Replay is the default.** `/desk/run` in replay mode returns the recorded run and streams it with its original timing. Say "this is the run recorded at 01:30, want me to run one live?" rather than letting a judge assume it is live.
2. **`ATLAS_ACTIONS=live` is set in `.env`.** Gmail and Linq really send on this machine. Either rehearse with `ATLAS_ACTIONS=dry` or accept that the click sends a real email.
3. **The tenant price is invented.** `tenant.py` says so in code (`LABEL`), the receipt prints it, and the pricing constants are documented as invented in `packs/toronto/PRICING.md`.
4. **Elastic and the layer cache degrade silently.** That is a feature (the demo survives a dead network) and a trap (you can show `[memory]` while claiming Elastic). Point at the backend badge every time.
5. **Two tests fail in this worktree.** `eval/test_backtest.py` needs `cache/layers/`, which is gitignored. It passes on the machine that ran the prefetch. Do not run `pytest` in front of a judge from a fresh clone without running `packs/us/prefetch.py` first.
